# 设计文档

> 对应 Issue：[开源实习] openGauss B库B协议适配MySQL python orm框架 Django #34  
> https://gitcode.com/opengauss/opensource-intership/issues/34

## 1. 项目背景

openGauss 在 dolphin 插件中实现了 MySQL 协议兼容。社区已有 JDBC / MyBatis / Hibernate 等指南，本任务补齐 **Python ORM（Django）+ MySQL Python 驱动** 经 dolphin 连接 B 兼容模式数据库的验证、适配与文档。

按社区评审要求：**优先支持原生 `django.db.backends.mysql`**；dolphin 缺少的 MySQL 变量/能力在 **Plugin** 仓补齐，而不是仅靠客户端自定义 Backend 绕过。

## 2. 目标与范围

| 目标 | 说明 |
|------|------|
| 连通性 | Django 经 `dolphin_server_port`（如 3308）完成认证与会话 |
| 原生 Backend | 使用官方 `django.db.backends.mysql` |
| Plugin 兼容 | 为 Django 探测变量提供兼容桩（无真实引擎语义） |
| 业务可用性 | 覆盖 ORM 查询与 CRUD 主路径 |
| 交付 | examples 示例/自测/思维导图；docs 开发指南；Plugin 补丁 |

**非目标：** 存储过程、server-side cursor 等协议明确不支持能力的强制支持；实现真实 InnoDB 引擎。

## 3. 环境约束

- OS：openEuler 20.03 LTS（x86_64 / aarch64）
- DB：openGauss 7.0.0-LTS（正式包未上架时可用 archive_test 转测包，需含 dolphin 的 Server 版，非 Lite）
- 协议：`enable_dolphin_proto=on`，`dolphin_server_port` ≠ 原生 port
- 客户端：Python 3.8+，Django 4.2+/5.0，PyMySQL（或 mysqlclient）

## 4. 总体方案

```text
Django App
  -> ENGINE=django.db.backends.mysql
    -> PyMySQL (MySQLdb 兼容层)
      -> TCP :dolphin_server_port
        -> openGauss B DB + dolphin
             @@default_storage_engine -> "InnoDB" (stub)
             @@sql_auto_is_null       -> 0 (stub, SET 可写)
```

### 4.1 服务端配置要点

1. 创建 B 库：`CREATE DATABASE ... DBCOMPATIBILITY 'B'`
2. `CREATE EXTENSION dolphin`（如需要）
3. `SELECT set_native_password(user, password, '')`
4. GUC：`listen_addresses`、`enable_dolphin_proto`、`dolphin_server_port`、`dolphin.default_database_name`

### 4.2 Plugin 适配要点（评审结论）

原生 Django MySQL backend 在 `mysql_server_data` 中会查询：

- `@@sql_mode`
- `@@default_storage_engine`  ← 原报错 **28804**（变量不存在）
- `@@sql_auto_is_null`
- `@@lower_case_table_names`
- 等

openGauss **没有** MySQL 存储引擎实现。参考 `contrib/dolphin/plugin_postgres.cpp` 中 `query_cache_size` / `system_time_zone` 等“无实际语义、仅兼容客户端探测”的变量做法：

1. 在 `BSqlPluginContext` 增加字段
2. `DefineCustomStringVariable("default_storage_engine", ...)` 默认 `"InnoDB"`
3. `DefineCustomIntVariable("sql_auto_is_null", ...)` 默认 `0`（支持 Django `SET SQL_AUTO_IS_NULL = 0`）
4. SET 时打 WARNING 标明无实际含义（与现有 stub 一致）

这样框架可正常初始化，且不引入虚假引擎能力。

另外，Django 用 `re.match()` 解析 `SELECT VERSION()`，要求字符串**以** `X.Y.Z` 开头。内核 `version()` 是 builtin，无法 `CREATE OR REPLACE`；dolphin 握手包已是 `8.0.28-dophin-server`。示例里 `pymysql_bootstrap.py` 在识别到 openGauss banner 时按握手版本解析为 `(8, 0, 28)`，从而继续走原生 `django.db.backends.mysql`。

### 4.3 示例业务

- Schema/DB：`mysql_test_db`
- 表：`user(id, name, age)`
- 脚本：`scripts/run_demo.py`（查询/增/改/删）
- 过渡：未合入 Plugin 的环境可设 `OG_MYSQL_ENGINE=opengauss_mysql`

## 5. 测试设计

| 编号 | 场景 | 通过标准 |
|------|------|----------|
| T0 | 版本与进程 | `gs_ctl status` running |
| T1 | 端口 | 5432 / 3308 LISTEN |
| T2 | 协议认证 | PyMySQL 握手成功 |
| T3 | DDL | 建库建表成功 |
| T4 | `SELECT @@default_storage_engine` | 返回 `InnoDB` |
| T5 | ORM CRUD（原生 mysql backend） | 打印 `DEMO_OK` |
| T6 | Django 安装检查 | 打印 `INSTALL_OK` |
| T7 | 不支持项 | 文档标注跳过 |

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 正式 LTS 包不可得 | 使用同系列 archive_test 转测包并在报告中说明 |
| Lite 无 dolphin | 强制 Server/企业版 |
| 敏感信息入库 | 密码仅通过环境变量注入，文档脱敏 |
| 协议能力差异 | 文档明确不支持项，避免误用 |
| 兼容桩被误用为真实引擎能力 | 文档/WARNING 标明无实际含义 |
