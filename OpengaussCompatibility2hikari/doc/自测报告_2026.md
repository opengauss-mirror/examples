# 自测报告

> 验证类：com.linyu.ospp.HikariVerificationRunner
> 数据库：openGauss 7.0.0-RC3（B 兼容库 + dolphin）
> 驱动：MySQL Connector/J 8.0.20 + HikariCP 5.1.0

## 一、基本信息

关键词：HikariCP；MySQL JDBC；openGauss B 兼容库；dolphin；连接池

摘要：在 openGauss 7.0.0-RC3 的 B 兼容库与 dolphin 环境下，使用 HikariCP 5.1.0 配合 MySQL Connector/J 8.0.20 验证通过 MySQL 协议连接 openGauss 的可行性，覆盖建连、基础 SQL、CRUD 与连接池参数生效等场景。

## 二、环境与准备

- 数据库：openGauss 7.0.0-RC3（B 兼容库，dolphin 插件）
- JDBC 驱动：MySQL Connector/J 8.0.20
- 连接池：HikariCP 5.1.0
- 连接串：`jdbc:mysql://<host>:3306/<db>?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true`
- 用户：需通过 `set_native_password` 设置 MySQL 原生密码，否则 Connector/J 在公钥检索阶段无法认证。

## 三、验证结果

### 3.1 连接与基础能力

- 连接池初始化正常，`HikariPool` 成功建立物理连接。
- `Connection.isValid` 返回 true。
- `SELECT 1` 返回 1。
- `SELECT version()` 返回 `(openGauss 7.0.0-RC3 build f08516a2)`，确认服务端为 openGauss 而非 MySQL。
- 版本探测、系统变量查询均正常完成。

### 3.2 CRUD

- INSERT：成功写入业务表记录。
- SELECT：可查询写入结果与基础数据。
- UPDATE：成功更新记录字段。
- DELETE：成功删除记录。

### 3.3 事务

- 使用显式事务完成提交，提交后数据可查询。
- 隔离级别探测正常，未出现无法映射 `default` 的建连失败。

### 3.4 连接池参数

- `maximumPoolSize`、`connectionTimeout`、`maxLifetime`、`keepaliveTime` 等参数按配置生效。
- 借满 `maximumPoolSize` 后，再申请连接进入等待，不突破上限；释放后等待请求恢复执行。

### 3.5 并发

- 10 个 worker 各自持有连接完成 insert/select/update/select/delete/commit，全部成功。

## 四、历史兼容性说明

开源之夏 2024 报告曾记录 MySQL 驱动经 HikariCP 无法建连，根因是早期 dolphin 版本对 `SELECT @@session.transaction_isolation` 返回字面量 `default`（更早版本报 `missing FROM-clause entry for table "session"`），HikariCP 探测隔离级别时无法映射而建连失败。版本边界为 6.0.0-RC1（dolphin）可复现，7.0.0-RC3（dolphin 5.2）已不复现。本次在 7.0.0-RC3 下实跑，连接与事务均正常。

## 五、结论

在 openGauss 7.0.0-RC3（B 兼容库 + dolphin）环境下，HikariCP 5.1.0 配合 MySQL Connector/J 8.0.20 可经 MySQL 协议正常连接 openGauss，并完成建连、CRUD、事务、连接池参数生效与并发操作验证。
