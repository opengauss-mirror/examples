## 4. 关键场景

### 4.1 配置文件到连接池实例

`DbcpDataSourceTest#testPoolConfigLoaded` 验证以下链路：

```text
dbcp.properties
  -> TestConfig.load()
  -> BasicDataSourceFactory.create(Properties)
  -> BasicDataSource
```

测试逐项读取并断言 URL、用户名、`initialSize`、`maxTotal`、`maxIdle`、`minIdle`、
`maxWaitMillis`、`validationQuery`、`testOnBorrow`、`testWhileIdle`、
`timeBetweenEvictionRunsMillis` 和 `minEvictableIdleTimeMillis`，确认配置文件中的参数
已应用到实际连接池实例；其中 `timeBetweenEvictionRunsMillis=60000` 用于启用 DBCP
空闲连接维护线程，使 `testWhileIdle` 能定期校验空闲连接。

### 4.2 满池等待与恢复

`ConnectionPoolTest#testMaxTotalConcurrentCrudAndQueuedBorrow` 设置 `maxTotal=8`：

1. 同时借出 8 条连接。
2. 每条连接执行 `INSERT -> SELECT -> UPDATE -> SELECT -> DELETE -> COMMIT` 并保持占用。
3. 第 9 条请求进入等待，活动连接数始终不超过 8。
4. 不释放连接时，第 9 条请求在 `maxWaitMillis` 后超时。
5. 释放连接后，新请求可以重新借到连接并执行 `SELECT 1`。
6. 测试结束时 `numActive=0`。

### 4.3 并发业务

`StabilityTest#testConcurrentCrudLoad` 使用 16 个工作线程，每个线程持有独立连接完成一次
事务 CRUD，所有线程提交后均清理测试数据，最终活动连接数为 0。

高负载验证固定 `maxTotal=128`：

| 场景 | 结果 |
|---|---|
| 128 条连接同时执行事务 CRUD | 全部完成，结束 `active=0` |
| 256～5000 个业务请求排队复用 128 条连接 | 各档均完成，结束 `active=0` |

请求数表示业务任务数量，连接池创建的物理连接数始终受 `maxTotal` 限制。

### 4.4 事务

| 场景 | 断言 |
|---|---|
| 自动提交 | 新连接的 `autoCommit` 为 `true` |
| 提交 | `commit()` 后，其他连接可以查询到已提交数据 |
| 回滚 | `rollback()` 后，其他连接查询不到回滚数据 |
| 隔离级别 | 可以设置并读取 `TRANSACTION_READ_COMMITTED` 和 `TRANSACTION_REPEATABLE_READ` |
| 池化连接 | 通过 DBCP 包装连接执行事务，归还后连接状态恢复 |

### 4.5 DDL、DML、DQL、DCL、TCL

| 分类 | 操作 | 断言 |
|---|---|---|
| DDL | `CREATE TABLE`、`ALTER TABLE`、`TRUNCATE TABLE`、`DROP TABLE` | 对象创建、结构变更、清空和删除成功 |
| DML | `INSERT`、`UPDATE`、`DELETE` | 影响行数和最终数据正确 |
| DQL | 条件查询、排序、`COUNT(*)` | 结果顺序、行数和聚合值正确 |
| DCL | `GRANT SELECT`、`REVOKE SELECT` | 授权后权限存在，撤销后权限消失 |
| TCL | `COMMIT`、`ROLLBACK` | 提交数据可见，回滚数据不可见 |

DCL 用例使用临时角色和临时表，执行账号需要管理员权限或 `CREATEROLE` 权限。所有临时
对象均在测试结束时清理。

### 4.6 断连恢复

`ConnectionValidationTest` 通过独立管理连接终止被测服务端会话，然后验证：

- `testOnBorrow=true` 时，借连接前发现失效连接并创建新的物理连接。
- `testWhileIdle=true` 且 `timeBetweenEvictionRunsMillis=60000` 时，维护线程从空闲池中清除失效连接。
- 新连接可以继续执行 `SELECT 1`。

## 5. Spring Boot 连接链路验证

examples 工程提供 Spring Boot 2.5.6、DBCP2 2.9.0、Connector/J 8.0.28 的可运行链路示例，
并在 VM 的 master 分支转测包实例中完成启动验证：

```text
SpringApplication.run()
  -> DataSourceAutoConfiguration
  -> BasicDataSource（DBCP2）/ PoolableConnection
  -> com.mysql.cj.jdbc.ConnectionImpl
  -> Dolphin MySQL 协议端口
  -> openGauss B 兼容库
  -> JdbcTemplate / TransactionTemplate
```

运行时确认数据源类型和连接池参数；`JdbcTemplate` 完成查询，
`TransactionTemplate` 完成提交和回滚，临时数据清理成功。

VM 内执行命令（密码通过环境变量传入，以下账号为临时测试账号）：

```bash
DBCP_URL='jdbc:mysql://127.0.0.1:36443/mysql_test_db?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC&characterEncoding=utf-8&zeroDateTimeBehavior=CONVERT_TO_NULL' \
DBCP_USER='<DBCP_USER>' DBCP_PASSWORD='<DBCP_PASSWORD>' mvn spring-boot:run
```

VM 验证实例：openGauss 7.0.0 master 分支转测包，PostgreSQL 端口 `36432`，Dolphin
MySQL 协议端口 `36443`，JDK 1.8.0_472。
执行结果：

```text
Spring 注入数据源: org.apache.commons.dbcp2.BasicDataSource
DBCP 参数: initialSize=2, maxTotal=8, maxWaitMillis=5000, testWhileIdle=true, timeBetweenEvictionRunsMillis=60000, minEvictableIdleTimeMillis=300000
JdbcTemplate 查询 user 表: 3 行
TransactionTemplate COMMIT 后查询到 1 行
TransactionTemplate ROLLBACK 后查询到 0 行
Spring Boot DBCP 链路验证完成，临时数据已清理
```

该验证确认 Spring Boot 自动配置实际创建的是 DBCP `BasicDataSource`，并通过
`JdbcTemplate` 完成查询、`TransactionTemplate` 完成提交和回滚。VM 验证使用专用测试账号，
并为自增列授予了 schema 下序列权限：

```sql
GRANT ALL ON ALL SEQUENCES IN SCHEMA mysql_test_db TO <DBCP_USER>;
```

## 6. 结论

在本报告所列环境中，DBCP2 2.9.0 可以通过 Connector/J 8.0.28 和 Dolphin MySQL 协议
连接 openGauss B 兼容库。连接池配置、CRUD、事务、满池等待、并发业务、断连恢复以及
DDL、DML、DQL、DCL、TCL 操作均通过验证。
