## 1. 项目目标

验证 Python ORM 框架 Peewee 配合 PyMySQL 驱动，通过 Dolphin MySQL 协议连接 openGauss B 兼容模式数据库的可用性，并产出：

- 可重复执行的 pytest 自动化测试；
- 测试思维导图与用例清单；
- 自测报告及缺陷证据；
- Peewee 开发指导文档。

测试链路如下：

```text
Peewee ORM
    → PyMySQL 驱动
    → Dolphin MySQL 协议
    → openGauss B 兼容物理数据库
    → MySQL database 参数对应的业务 schema
```

## 5. 严格验收断言

### 5.1 TC-01-05：元数据内省

测试表：

```sql
CREATE TABLE test_conn_t3 (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    remark TEXT NULL,
    price DECIMAL(10,2) DEFAULT 0.00
);
```

自动化测试直接断言以下协议结果：

```text
SHOW INDEX.Key_name                            = PRIMARY
information_schema.columns.id.extra           = auto_increment
information_schema.columns.price.data_type    = decimal
information_schema.columns.price.column_type  = decimal(10,2)
```

并直接调用 Peewee `MySQLDatabase.get_columns()` 断言：

```text
id.primary_key  = True
id.identity     = True
price.data_type = decimal
price.full_type = decimal(10,2)
```

原始 RC3 环境的主要差异：

```text
SHOW INDEX.Key_name = test_conn_t3_pkey
id.extra             = AUTO_INCREMENT
price.data_type      = number
price.column_type    = number
id.primary_key       = False
id.identity          = False
```

因此原始版本的严格断言失败，记为 OBS-001。

### 5.2 TC-09-04：重复键异常映射

测试分别从 PyMySQL 和 Peewee 两层执行重复唯一键插入，不捕获宽泛的 `Exception`：

```text
PyMySQL 预期异常 = pymysql.err.IntegrityError
Peewee 预期异常  = peewee.IntegrityError
MySQL 错误码     = 1062
MySQL SQLSTATE   = 23000（由协议/JDBC 回归覆盖）
```

原始 RC3 环境返回：

```text
pymysql.err.OperationalError:
(20674, 'duplicate key value violates unique constraint ...')
```

因此原始版本的严格断言失败，记为 OBS-002。

## 6. 缺陷与修复追踪

统一进度跟踪：

历史缺陷记录：

### 6.1 OBS-001：元数据不符合 MySQL/Peewee 预期

影响：依赖数据库反射、动态模型或自动识别主键的 Peewee 应用无法取得完整元数据。

修复由以下改动共同组成：

| 仓库/PR | 修复内容 | 当前状态 |
|---|---|---|
| Plugin #2551（上游已合入） | 将 MySQL 协议元数据中的 openGauss 类型名映射为 MySQL 类型名 | 已作为后续 PR 基线 |
| Plugin #2553 | `SHOW INDEX` 的主键名返回 `PRIMARY` | 已合入；最终联合验证 PASS |
| openGauss-server #9709 | `extra` 返回小写 `auto_increment`；`COLUMN_TYPE` 使用 `a.atttypmod` 保留 DECIMAL 精度；提供安装、升级及回滚脚本 | 已合入；最终联合验证 PASS |

相关 PR：

- <https://gitcode.com/opengauss/Plugin/pull/2553>
- <https://gitcode.com/opengauss/openGauss-server/pull/9709>
- <https://gitcode.com/opengauss/docs/pull/8846>

### 6.2 OBS-002：重复键错误分类不兼容

影响：常规的 `except IntegrityError` 无法捕获重复键，应用的事务处理或幂等逻辑可能走入错误分支。

Plugin PR #2553 的实现范围：

- 仅对可确认的存储层重复键路径映射 MySQL 1062/23000；
- 不把其他 SQLSTATE 23505 场景统一误报为重复数据；
- 优先保留 SIGNAL/RESIGNAL 显式指定的 `MYSQL_ERRNO` 和 SQLSTATE；
- JDBC 回归直接断言重复键、普通 SIGNAL 和显式 SIGNAL/RESIGNAL。

当前状态：Plugin #2553 已合入；包含 Server/Plugin master 的最终联合验证已完成并通过。

## 8. 测试代码自查修正

| 编号 | 初始问题 | 修正方式 |
|---|---|---|
| TEST-001 | 将批量插入返回值误当作 rowcount | 使用 `.as_rowcount()`，并查询实际行数 |
| TEST-002 | 使用 Peewee 4.3.0 不存在的 `update_or_insert` | 改用 `get_or_create` 幂等测试 |
| TEST-003 | AND 条件期望行数计算错误 | 改为断言具体记录 |
| TEST-004 | `contains('an')` 漏算匹配记录 | 改为断言完整名称列表 |
| TEST-005 | 元数据测试只打印结果，缺少强断言 | 增加协议原始值和 Peewee `get_columns()` 逐项断言 |
| TEST-006 | 重复键测试仅覆盖 Peewee 层，异常后未显式保证事务清理 | 增加 PyMySQL 和 Peewee 两层精确异常类型及 1062 错误码断言；PyMySQL 使用独立事务并在 `finally` 中 rollback，Peewee 让异常穿过 `db.atomic()` 自动回滚 |
| TEST-007 | 数据库连接失败时跳过全部测试，可能被误认为兼容性通过 | 连接或 autocommit 验证失败时直接 FAIL，不允许以 skipped 代替验收通过 |
| TEST-008 | `except Exception` / `pytest.raises(Exception)` 会接受无报错或无关异常，形成假 PASS | 对当前协议实际返回的 `peewee.InternalError`、514/132 错误码和认证/缺表特征进行精确断言，并加入“SQL 正常返回”和“无关异常”反例 |
| TEST-009 | 认证失败测试绕过 `config.ini`，可能因连接目标错误而 PASS | 复用已连接 `db` 的最终有效参数，只构造一个确定不同的密码；同时验证未设置环境变量时 `config.ini` 的完整加载路径 |
| TEST-010 | `other = db` 没有创建独立连接，无法证明自动提交可见性 | 新建并打开独立 `MySQLDatabase`，确认底层连接对象不同；验证自动提交记录立即可见、显式事务未提交记录不可见 |
| TEST-011 | `IntegerField(default=0)` 只验证 Peewee 客户端默认值 | DDL 显式增加数据库 `DEFAULT 0`，使用省略该列的原生 INSERT，并重新 SELECT 验证实际落库值 |
| TEST-012 | 清理按表名顺序 DROP 且吞掉异常，外键父表可能残留 | 基于外键依赖图先删子表/中间表再删父表；元数据、DROP 或残留检查失败均使 teardown 报错 |
| TEST-013 | 隔离级别查询失败时仅打印提示，仍会 PASS | 改为必须返回非空隔离级别，查询异常直接使测试失败 |
| TEST-014 | 默认 `ConfigParser` 会插值并破坏含 `%` 或 `%(...)s` 的合法密码 | 禁用配置插值，并验证 config.ini 原样读取以及 `PEEWEE_TEST_*` 环境变量优先级 |
