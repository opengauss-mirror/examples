# GORM 连接 openGauss B 兼容模式设计说明

## 1. 背景与目标

本示例验证 GORM 结合 MySQL Go 驱动，通过 openGauss Dolphin 的 MySQL 协议连接 openGauss B 兼容模式数据库，并提供可重复执行的迁移和基本 CRUD 示例。

## 2. 总体方案

应用使用 `gorm.io/driver/mysql` 和 `github.com/go-sql-driver/mysql` 建立协议连接。示例在 GORM MySQL Dialector 外增加 openGauss 迁移器包装，保留通用 SQL 和 CRUD 能力，同时替换 Dolphin 不兼容的 MySQL 元数据探测逻辑。

## 3. 关键设计

- 通过环境变量配置连接，真实认证信息不写入代码或文档。
- 使用 `SkipInitializeWithVersion`，避免按 MySQL 规则解析 openGauss 版本字符串。
- 使用 `SELECT DATABASE()` 获取当前数据库名。
- 使用 Dolphin 可用的 `information_schema.tables`、`information_schema.columns` 和 `information_schema.statistics` 查询表、列和索引信息。
- 将迁移适配限制在示例客户端，不修改 openGauss-server 或 Plugin 仓代码。
- 使用 `context.Context`、参数化 SQL 和连接池配置支持基本生产使用方式。

## 4. 模块划分

| 模块 | 职责 |
|---|---|
| `internal/config` | 环境变量读取、DSN 构造和校验 |
| `internal/db` | GORM 初始化、Dolphin 迁移适配、健康检查和连接池 |
| `internal/model` | 示例数据模型 |
| `internal/repository` | 参数化 CRUD 和错误处理 |
| `cmd/gorm-opengauss` | health、migrate、crud 命令入口 |
| `docs` | 测试思维导图、自测报告和联调证据 |

## 5. 测试与风险

本地使用 Go 单元测试、sqlmock 和 `go vet` 验证；真实环境验证重复迁移和基本 CRUD。索引/列重命名、时间精度、并发压力、多版本 Dolphin 及 aarch64 仍需按目标环境单独验证。
